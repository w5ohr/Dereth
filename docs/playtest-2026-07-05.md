### ✅ #21 (windows) — FIXED (2026-07-06) — glass panes now translucent + lamplit at night
**Fixed on `fix-window-transparency`.** The earlier "baked into textures" diagnosis was
half-right: a full sweep of all 846 town models + their textures showed the wall art contains

the visual behind the original user report). Fix:
- `_tbMarker` widened to classify the saturated placeholder family as glass — **+60 panes across
  the world** (verified against all models: only garish placeholder hues caught; muted paints
  like pale sage/lavender correctly excluded), joining the 63 pure-blue panes;
- glass material made properly glassy (opacity 0.42, roughness 0.08) with a **warm emissive
  driven by the day/night cycle** in `updateDayNight` (0.05 daytime sheen → 0.75 lamplit glow at
  night, matching the #21-doorway interior-card art direction); materials registered with
  dispose-aware pruning (#22 hygiene).
Verified live: neon quads gone, panes translucent, glow state follows the clock (0.75 at forced

### ✅ #22 — FIXED (2026-07-06) — GPU geometry/texture counts grew without bound (slow leak)
**Fixed on `fix-gpu-resource-leak`.** Root cause: a family of permanent-removal paths called
`scene.remove` without disposing GPU resources. All now route through `disposeObject3D` (or
material-only disposal where the texture is shared): **dead monsters** (the `dying[]` shrink
animation + `clearDying` + world rebuild — the dominant churner: every kill leaked the mob's body
geometry and skin texture), **floaters** (every damage number owns a CanvasTexture), **projectiles
and spell walls** (a SphereGeometry per arrow/bolt, in-flight expiry + `clearProjectiles`),
**looted drops** + `clearDrops`, **burst particles / firework rockets** (material-only — the CIRC
map is shared), and the **label registry** (`disposeObject3D` unregisters disposed nametags from
`LABELS`; the orphan-pruners now dispose the CanvasTextures they previously stranded).
**Verified:** an instrumented single kill-cycle (spawn → kill → dispose → clear drops) has a
renderer delta of **zero** and an exactly-unchanged reachable-texture set; a same-ground combat
window shows **+21 geometries over 191s / 153 kills** (pre-fix: +205 per 140s); respawns of a
disposed kind render fully (24/24 meshes), floaters/bursts still show, zero console errors.
Remaining growth while exploring NEW territory is first-time content upload (legitimate).
**✅ Adjacent gap now fixed (2026-07-06):** *unlooted ground drops never expired.* Loose **gold** had
no despawn path at all (only the walk-over `dd<2` pickup removed it — hence the 105 stray piles), and
the item/corpse timed-expiry branches still called `scene.remove` (leaking the mesh's geometry/material
even when they did fire). The drop update loop now despawns loose **gold** on the same 45s timer as item
loot (corpse-spill items still ~10min), and every timed expiry routes through `disposeObject3D`.
Shared/online drops stay server-authoritative (never client-despawned); the player's corpse ttl is
unchanged. Verified in-harness: gold despawns at 45s, shared gold persists, item/corpse-spill/corpse
timers all correct, 0 errors. (`update` drop loop.) (Soak pass → fixed same day.)

Found by the first dedicated **soak test** (7 min of continuous real-frame play, auto-run wandering
between Holtburg and one fixed wilds spot, sampled via `renderer.info`): **geometries 1,929 → 2,986
(+55%) and textures 296 → 636 (+115%)**, still climbing at the final sample **including across a
revisit of the exact same two areas** (+205 geoms / +97 textures in the last 140s loop over ground
already streamed) — the no-plateau signature of a disposal leak, not one-time asset caching.
Everything else held perfectly flat or healthy over the soak: JS heap 1,698 → 1,396 MB (GC settles,
no heap leak), scene children / obstacles / bursts / floaters constant, frame counter advancing at
a steady ~300/s with no decay, zero console errors, and two organic wilds deaths respawned cleanly
(Vitae stacking + decay observed working).

**Confirmed contributor:** `labelSprite()` allocates a fresh 256×64 `CanvasTexture` per call (every
streamed mob's nametag, corpse label, etc.) and registers the sprite in the global `LABELS` array —
the pruning pass (`LABELS.splice` on unparented sprites) removes array entries but **never calls
`texture.dispose()`**, so canvas textures accumulate in the renderer for every label whose owner was
removed by a path other than `disposeObject3D`. The geometry growth (+1,057) is a second source —
label sprites carry no geometry — pointing at streamed-entity meshes (mob bodies/health bars/corpse
props/FX rings) not fully reaching `disposeObject3D`.

Impact: a long play session (hours) leaks thousands of GPU resources → VRAM growth and eventual
renderer degradation, invisible in short sessions. **Fix direction:** dispose the sprite material's
map in the LABELS pruning pass; audit every streamed-entity teardown path to route through
`disposeObject3D`; consider surfacing `renderer.info.memory` in the debug HUD so regressions are
visible. (Soak pass, `labelSprite`/`LABELS`, `disposeObject3D` callers.)

## FIXED — 2026-07-06 (Opus follow-up: code fixes for logged findings #11, #15, #16, #17)

All four fixed in one branch and verified in-harness (state-based). No combat regression: melee (952),
spell war-bolt (209), and arrows (2546) all still deal damage; a real save still round-trips; zero
console errors.

- **✅ #11 — Ranged arrows dealt no damage on elevated terrain (RE-DIAGNOSED, was "projectile tunneling").**
  The real cause wasn't per-frame tunnelling — `fireArrow` spawned the arrow at **absolute** `oy=EYE-0.1`
  (≈1.6) instead of the player's eye height, so on any ground above sea level (verified at the Academy,
  ground ≈35) the arrow spawned ~33u **underground** and was culled by the terrain `hitGround` check
  before it moved; the collision band `Math.abs(p.y-1)<1.8` was likewise sea-level-only. So arrow/crossbow/
  atlatl combat did **zero** damage across most of the 1:1 map. (Spell bolts escaped it — `grav:false`,
  culled only below y=0.1, 2D collision.) **Fix:** spawn at `player.y+EYE-0.1`; make the hit-band
  ground-relative (`Math.abs(p.y-(gh+1))<1.8`, `gh=0` for flat bolts → unchanged); **plus** a swept
  segment-vs-circle test (`_segHit`) so fast shots also can't tunnel between frames. **Verified:** a bow on
  ground 35 now lands hits (2481 dmg where it was 0); melee/bolts unaffected. (`fireArrow`, `updateProjectiles`.)
- **✅ #15 — `applySaveObj` hard-crashed on a malformed/partial save.** Core fields were assigned raw, so a
  valid-JSON save missing `attr` set `player.attr=undefined` and every read threw. **Fix:** default+sanitize
  the core fields (`attr` rebuilt from a fresh base keeping only finite >0 values; `level|xp|xpUnspent|
  skillPts` numeric-coerced; `inv`/`salvage`/`kills`/`gold`/`armor` type-guarded) and wrap `applySaveObj` in
  try/catch (fall back to a fresh character). **Verified:** 7 malformed saves (empty, null, wrong-types,
  NaN/Infinity attrs, extremes, arrays-as-objects, nested-bad) all load safely; a real save still
  round-trips. (`applySave`, `applySaveObj`.)
- **✅ #16 — `damageMonster` didn't guard NaN/negative damage** (NaN → un-killable mob, negative → healed).
  **Fix:** `dmg=Math.max(0,+dmg||0)` at entry — immunises every damage source. **Verified:** NaN and −50
  both leave HP unchanged at 100. (`damageMonster`.)
- **✅ #17 — Repositioning while aboard a ship (death / recall / map-travel) was undone by re-pinning.**
  `updateShipPilot` re-pinned the player to the ship every frame and nothing cleared `aboardShip` on an
  `arriveAt`. **Fix:** clear `player.aboardShip` inside `arriveAt()` (one change covers death-respawn,
  recall, portals, map-travel — the ship stays floating), and early-return `updateShipPilot` when
  `!player.alive`. **Verified:** death-while-aboard clears the flag, map fast-travel keeps you at the
  destination (not re-pinned), boarding still works. (`arriveAt`, `updateShipPilot`, `die()`.)

## Candidates investigated → NOT bugs (harness test-input artifacts)

From the systems pass — each traced in source and confirmed as a test-setup mistake, not a game bug:
- **Missile ammo "not consumed" / 0-count fires** — read the wrong ammo stack (crossbow quarrels vs
  bow arrows) and forced an impossible `count:0` stack; `fireArrow` does consume ammo and
  `takeFromInv` removes a stack at count 0.
- **Attr buff "no-op"** — the Creature school was never trained (out of *skill credits*, which come
  from leveling, not granted XP), so `canCast` correctly rejected the cast. Confirmed working when
  force-trained.
- **Tinker "no-op" on a bow** — `MAT_APPLY['Steel']` resolves to **armor** (armor loop wins), so a
  Steel bag on a weapon is a no-op by design; weapon tinks need a weapon-class material (Titanium).
- **"Stuck" cast** — headless frame sparsity + `dt` clamp (0.05/frame) means 2.5s wall ≪ 0.4s cast
  time in a heavy scene; the loop is alive, the cast just hadn't finished. Test effects via the
  instant `executeSpell` path.

## Test-harness notes (not game bugs)

- **`WrongDocumentError … pointer lock`** — thrown by `cEl.requestPointerLock()` in `startGame()`
  under headless (no user gesture). Harmless; runs inside a click handler in a real browser.
- **Boot is heavy** — `startGame()` → `buildWorld()` builds the ~4M-vertex terrain (GROUND_SEG 2000)
  synchronously (~30s under software WebGL). Real-GPU cost is negligible.
- **Sparse headless frames + `dt` clamp** — `loop()` clamps `dt=min(dt,0.05)`; under SwiftShader with
  a heavy scene, game-time advances far slower than wall-clock, skewing time-based tests (cast bars,
  projectile travel). Verify such effects via instant paths or give generous waits.
- **Adaptive graphics downgrade** — the ~0.5fps headless loop trips the "frame rate dipped below 30
  → step graphics down" system, so some earlier "over-bright/washed-out" observations were captured
  in a downgraded state, not true bugs. Re-verify any *lighting/texture-wash* finding at forced-High
  on real hardware. (Structural/geometry findings — buried-y, scale — are quality-independent.)
- **Out-of-loop `renderComposite()`** with `running=false` corrupts the post-processing render
  targets → black viewport. Harness artifact, recovered by reload; not a game bug.
